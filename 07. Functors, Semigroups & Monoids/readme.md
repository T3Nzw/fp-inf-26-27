# Функтори, полугрупи и моноиди

## Полугрупа

Полугрупа е понятие, идващо от абстрактната алгебра.
Дефинира се като множество, което е затворено относно
някаква двуместна асоциативна операция.

В `Haskell` има тип, който представя именно тази абстракция за полугрупа:

```hs
class Semigroup a where
  (<>) :: a -> a -> a
  sconcat :: NonEmpty a -> a
  stimes :: Integral b => b -> a -> a
```

Полугрупите се използват на места, където ни е необходимо
да можем да абстрахираме операция на обединение на елементи
по някакъв начин, който да е специфичен за даден тип.

- list, maybe, predicate, error streams

## Моноид

Моноидът е полугрупа, която има неутрален елемент
относно операцията. В Haskell също има такава абстракция:

```hs
class Semigroup a => Monoid a where
  mempty :: a
  mappend :: a -> a -> a
  mconcat :: [a] -> a
```

## Higher-kinded types

Обикновените типове в Haskell (като `Int`, `Bool`, `Char`) имат kind `*`
(или `Type`) – те са "готови" (complete) типове, от които могат да съществуват стойности.

Типовите конструктори (като `Maybe`, `[]`, `Either String`) приемат тип и връщат нов тип. Те имат по-висок kind, например:

- `[] :: * -> *`;
- `Maybe :: * -> *`;
- `Either :: * -> * -> *`;
- `(->) :: * -> * -> * (типовият конструктор на функцията a -> b)`.

Higher-kinded types са типове (или типови параметри),
които сами по себе си приемат типови конструктори
(тоест имат kind от вида `(* -> *) -> ...`).
Именно те позволяват да дефинираме абстракции като функтори,
апликативни функтори, монади и др.

Самите имена на типови класове също имат свои типови сигнатури,
които все още не сме виждали. Например, за горните два типови класа:

```hs
-- type Semigroup :: * -> Constraint
type Semigroup :: Type -> Constraint
class Semigroup a where ...
```

```hs
-- type Monoid :: * -> Constraint
type Monoid :: Type -> Constraint
class Monoid a where ...
```

*Забележка*: За да напишете експлицитно горните,
трябва да import-нете `Type` и `Constraint` от
`Data.Kind`. Също така, може да се наложи да
използвате и разширения на езика, в зависимост
от настройките на компилатора: `{-# LANGUAGE StandaloneKindSignatures, ConstraintKinds #-}`.

#### Всеки типов клас е конструктор на ограничения и ни връща `Constraint`.

## Функтор

В действителност има различни видове функтори.
Функторите са абстракция, която представя структура,
върху която можем да прилагаме функция върху всеки
от елементите ѝ, без да променя самата структура.
Вече сме виждали пример за това - списъци,
в лицето на функцията `map :: (a -> b) -> [a] -> [b]`.
Тази типова сигнатура може да бъде записана по още
един начин: `map :: (a -> b) -> [] a -> [] b`, т.е.
прилагаме типовия конструктор `[]` над някакъв тип `a`/`b`.
Де факто `[a]` е просто синтактична захар за `[] a`.
Може да си мислите, че `[]` е просто синтактична захар
за тип, аналогичен на `List`, който сме писали.
Тази еквивалентност ще бъде важна по-надолу.

Ще започнем с най-често срещания такъв.

### Ковариантен функтор

Или само функтор. В Haskell се дефинира по следния начин:

```hs
class Functor f where
  fmap :: (a -> b) -> f a -> f b
```

Примери за функтори са `[]`, `Maybe`, `Either a`, `(,) a`
и т.н.

За да бъде даден тип функтор, трябва да бъдат в сила следните
два закона:

- закон за идентита: `fmap id == id`;
- закон за композицията/дистрибутивността: `fmap (g . f) == fmap g . fmap f`.

### Бифунктор

Бифункторът обобщава ковариантния функтор до два типови параметъра,
като позволява да прилагаме функции и върху двата аргумента
(и двата параметъра са ковариантни). Дефиниран в `Data.Bifunctor`:

```hs
class Bifunctor p where
  bimap :: (a -> b) -> (c -> d) -> p a c -> p b d
  first :: (a -> b) -> p a c -> p b c
  second :: (c -> d) -> p a c -> p a d
```

Класически примери са наредената двойка `(,)` и `Either`.

### Контравариантен функтор

Докато при ковариантния функтор стрелката на функцията е "напред"
`((a -> b) -> f a -> f b)`, контравариантният функтор я "обръща" назад
`((b -> a) -> f a -> f b)`. В `Data.Functor.Contravariant`:

```hs
class Contravariant f where
  contramap :: (b -> a) -> f a -> f b
```

Типичен пример е тип, който консумира входни стойности,
вместо да ги произвежда – например `Predicate a`
или сравнение/хеш функция.

### Профунктор

Профункторът е двупараметров конструктор `(p :: * -> * -> *)`,
който е контравариантен по първия си аргумент и ковариантен по втория.
В `Data.Profunctor`:

```hs
class Profunctor p where
  dimap :: (a -> b) -> (c -> d) -> p b c -> p a d
  lmap :: (a -> b) -> p b c -> p a c
  rmap :: (c -> d) -> p a c -> p a d
```

Най-известният пример за профунктор е самата функция `(->)`:
при функция `f :: b -> c`, можем да адаптираме входа ѝ с `a -> b` (`lmap`)
и да преобразуваме изхода ѝ с `c -> d` (`rmap`),
получавайки функция `a -> d`.
Профункторите са в основата и на *profunctor optics* (като `Lens`, `Prism`, `Traversal`).
